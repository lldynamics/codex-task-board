# 开发、协议与维护

面向开发者的技术资料。安装、语言切换、采集成本与隐私说明见[中文 README](../README.md)／[English README](../README.en.md)。以下功能记录保留其形成时的上下文；当前发布身份为 `codex-task-board`，旧工具名、数据路径和备份格式按兼容契约保留。

本机项目与任务管理 MCP App。当前源码版本 **0.11.0**：首次打开进入待处理，支持本机保存的“今日焦点”，已有视图偏好继续恢复；侧栏集中提供项目、定时计划与学习安排。任务支持阅读态与显式编辑、待处理原因分组、连续的主要状态列和可展开的自动来源详情。Codex 自动任务直接汇入“我的看板”，按主机和项目目录建立独立项目分组，继续提供自动采集快照与定时计划展示，保留项目侧栏、看板、列表、学习日历、编辑冲突处理、归档、导出恢复、版本化备份和请求重试保护。手工看板数据格式仍为 schema 4。

“我的看板”统一展示手工任务与来源明确的 Codex 自动任务。手工任务的六种状态由用户维护；自动卡片的状态随来源更新，不将空闲或一轮结束当成目标完成。Codex 可通过受限工具按用户要求记录普通任务、更新步骤和阻塞项、创建学习安排、记录用户明确提供的反馈；自动采集不读取对话正文、任务提示词或凭据。插件 ID 与 npm 包名统一为 `codex-task-board`，旧工具前缀与 `LearningBoard` 数据目录按[兼容契约](compatibility.md)保留。没有永久删除项目或任务的操作。

版本变更见 [CHANGELOG](../CHANGELOG.md)。历史验收记录引用的截图与日志属于本机资料，不随公开仓库分发；源码测试与预览不代表安装后的客户端已经验收。

## Codex 任务与定时计划

打开“我的看板”即可看到 Codex 自动任务，无须先切换标签。侧栏中每个“主机＋项目目录”都有独立的 Codex 项目分组，同名目录和不同主机不会被合并；无目录任务进入该主机的未关联项目组。搜索、筛选、分页和任务总数同时覆盖手工任务与自动任务。“定时计划”侧栏入口在工作台内容区展示已有计划，侧栏保持可用；“同步诊断”作为次级入口，只展示来源范围、采集时间、错误与刷新信息，不重复列出任务。首次读取 Codex 任务时会显示读取提示与暂定计数；读取失败会说明保留上次快照。

自动卡片与项目为只读投影，提供原任务入口和 ID，不参与手工拖动、编辑、归档、学习日历或备份导出。手工项目选项只包含真实手工项目。自动刷新及标签切换保留手工编辑草稿；采集不会修改手工任务、学习时段、revision 或备份。

- **自动任务卡片**：在“我的看板”中按项目筛选并按状态分组，支持搜索和分页，展示原任务标题、主机、项目路径、更新时间与来源。“本轮结束”仅指已有轮次结束证据；空闲、未加载、未知状态与本轮结束集中在可展开的“其他来源状态”，显示各自数量；搜索、状态筛选或仅含次要状态的项目会自动展开。只有明确的目标状态才能进入已完成。
- **状态证据**：空闲表示当前没有运行；未加载表示宿主尚未加载会话，两者均不表示目标完成。有效的本地轮次元数据可补充“本轮结束”；个别缺少时间的记录只影响其所属会话，不再丢弃其他有效轮次。真正缺少状态或采集过期时保留原因提示。
- **定时计划**：读取本机计划名称、启用/暂停状态和可用的上次/下次调度时间。上次调度时间不是成功证明；缺失字段显示未知，不从计划频率推测实际运行结果。自动化与每次运行不混为同一任务。
- **新建或调整计划**：直接在 Codex 对话中提出工作内容和时间。已有计划仅提供“复制暂停请求／复制恢复请求”，复制后在对话中发送；面板不会发送消息或修改计划。
- **时间与范围**：组件可见时每 5 秒读取本地快照，最新任务状态由用户配置的受信 Codex 会话采集，频率取决于该配置，不能称为秒级实时状态。线程和计划分别显示来源及最近成功时间。采集器记录相邻两次采集的间隔，快照在“两个间隔再加 1 分钟”内视为新鲜（最短 3 分钟、最长 35 分钟；尚无间隔时为 3 分钟）；超过后标为过期，不继续声称正在运行。例如每 15 分钟采集时，新鲜期为 31 分钟。`capturedAt` 若比服务端时钟超前不超过 5 分钟，按服务端时间记录，避免模型估计的时间被整批拒绝。
- **部分与断线**：原生列表当前最多返回最近 50 个非置顶任务，另含置顶任务；因此不能把这一批当成全量任务状态。更早的记录由桌面历史元数据补充，运行状态为未知。跨主机读取失败、结果截断或缓存损坏都有独立提示。部分采集保留此前记录，但未重新观测的运行状态不延续为实时。没有可信采集时，仅显示历史元数据。

当前桌面的 app-server 使用 stdio，普通插件无法直接连接其受信 app-tools 接口；本项目不绕过身份校验，不启动第二个 daemon 冒充全局状态源。采集使用 Codex 原生工具读取任务列表，再把白名单字段写入独立 `codex-snapshot.json`。看板服务只读该快照及本机 SQLite 元数据索引，不读取 prompt、正文、原始错误内容或认证文件。SQLite 是兼容适配，桌面版本变更或工具不可用时会明确降级。

### 自动采集入口

原生定时采集优先调用模型专用的 `learning_board_codex_sync`，以免后台采集依赖 shell 的额外目录权限。该工具严格限制为状态元数据，不提供线程控制或手工看板修改能力。采集使用独立 SQLite 事务锁；进程异常退出后由系统释放，锁文件可保留复用。缓存最多保留 1,000 条，达到上限时保留当前观测并淘汰最旧未观测元数据，仍明确标为部分范围；手工记录不受影响。首次验证或离线维护也可使用与插件一起分发的 CLI：

```sh
npm run codex:sync -- inspect
node plugins/codex-task-board/dist/codex-sync.js ingest < capture.json
```

`ingest` 只接受 `{capturedAt, limit, result:{pinnedThreads,threads,unavailableHosts,unavailableSources}}`，来源是受信的 Codex 任务列表；`capturedAt` 为采集完成的 UTC 时间。只保留 Codex 任务的必要元数据，按主机与 ID 去重，检查时间顺序，原子写入独立缓存。CLI 不接受生产数据目录覆盖。`inspect` 仅输出数量、采集时间和状态概要。

无人值守采集需要用户另行配置 Codex 原生定时任务；每次实际模型运行会占用 Codex 使用额度。启用后由该定时任务执行，不依赖看板页面打开；页面关闭期间不会进行前端轮询。原生本机任务需要电脑开机且 Codex 运行，可能排队或延迟。它只读取其他任务，不启动、暂停、结束或向其他任务发送消息。暂停采集可在 Codex 的定时任务界面操作；现有卡片随后显示过期。新增的业务定时任务仍需提供具体工作与时间。

## 日常使用

- 看板按计划中、进行中、等待用户、已完成分列；暂停和失败默认折叠，保留数量。列表视图与窄窗口保留相同记录与操作。
- 长列每页显示 50 项，上一页、下一页可以访问完整记录，列标题继续显示总数量。保存和移动后会定位到所在页；分页只影响查看，不改变已保存顺序。
- 项目、状态、来源及关键词可组合筛选。保存或移动后可定位相关任务，避免成功记录被当前筛选隐藏。
- 左侧导航提供待处理、全部任务、定时计划、学习安排、归档和项目列表，可查找项目并直接新建。无有效保存偏好时默认进入待处理；既有看板、列表或学习日历偏好继续恢复。“项目管理”提供所选项目的编辑和归档操作；归档视图中的项目入口保留归档范围。任务搜索、状态及来源筛选会继续生效，标签可逐项清除。状态按通用任务状态和 Codex 来源状态分组；记录类型可单独选择手工记录或 Codex 自动同步，来源工具明确显示“来源：Codex”等名称。
- 顶部工具栏集中搜索、看板/列表切换、筛选和新建任务。左侧导航在桌面可折叠，窄窗口变为抽屉，支持 Escape 关闭与键盘焦点循环；打开详情后回到可见的导航按钮。
- 看板卡片的“更多操作”菜单提供移动、排序与归档，支持键盘焦点和 Escape 关闭。已有手工任务先打开阅读详情，完整显示步骤和阻塞项；阅读态也提供状态与优先级快捷选择，选择后立即保存并提供撤销。点击“编辑任务”后修改文字、项目和截止日期；已有任务的状态与优先级在快捷选择中维护。返回阅读会保留草稿，离开时仍提示确认。新任务直接进入编辑，保存按钮固定在表单底部。自动任务保持只读，主机、完整目录和ID收进“来源详情”。
- 列表、阅读态和卡片菜单中的状态／优先级选择立即保存，选择当前值不会写入。撤销只修改刚才的字段，保留其他窗口更新的内容；若该字段已被再次修改，则停止撤销并说明原因。结果未知时保留原请求确认重试。
- 详情保存按钮旁显示当前保存状态。`N` 在今日/周日历中新建学习时段，在任务视图中新建任务；`/` 在任务视图聚焦搜索，`⌘ Enter` 或 `Ctrl Enter` 在编辑态保存详情，阅读态不会发起保存。在输入框内打字或使用中文输入法时，新建与搜索快捷键不会触发。
- 卡片日期在当年显示月日，完整日期可通过日期提示查看；未归档、未完成任务的过期日期会突出显示。保存成功提示短暂显示，冲突、未知结果及过期请求提示保留到明确处理。
- 任务可设置低、普通、高、紧急优先级，以及可选截止日期；待处理视图优先展示等待回复、失败和已到期的手工任务，以及可信新鲜快照中等待回复或失败的自动任务，卡片说明处理原因；计划中和进行中的其他任务进入“接下来”。到期包含显示时区的今天，已到期的暂停手工任务也保留提醒。过期的自动运行证据不产生新的待处理提醒。卡片截止标记与到期原因使用同一显示时区；可见页面跨日或从后台恢复会校准日期，编辑、拖动或保存期间保留当前布局，待安全时更新。组内按优先级和日期排序，共享每页50项分页；侧栏数量统计完整活动记录，搜索筛选只影响内容区。此查看顺序不改变已保存的手动列内顺序。
- 今日焦点可从手工任务的“更多操作”选择，在待处理顶部单独分组；选择及移除都会保存到本机。规则和备份兼容性见下方“今日焦点”。
- 已保存且没有修改的项目或任务禁用保存，输入改回原值也不生成备份；异常后保留的原请求仍可确认重试。
- 项目和任务可归档、恢复。项目归档会隐藏所属任务，不更改各任务自己的归档状态；恢复项目不会擅自恢复单独归档的任务。通过活动、归档或全部记录筛选查看。
- 完整表单的编辑须点击“保存到本机”；状态、优先级快捷选择立即保存。拖动及移动菜单只改变手动状态或顺序，不启动、暂停或终止 Codex 工作。归档也不会影响原对话。
- 未保存编辑在关闭或换任务时需要明确保留或放弃。另一窗口修改同一记录时，刷新后将未修改字段更新为最新值；双方修改同一字段且值不同，需要明确选择版本后保存。
- 视图、项目/状态/来源筛选及折叠偏好可以保存在组件的本地浏览器存储。该存储不保存任务内容、搜索文字、编辑草稿或写请求；不可用时降级为本次打开的设置。
- 桌面侧栏折叠偏好单独保存；抽屉打开状态和项目搜索不保存。切换项目或导航不会结束详情草稿，也不会改变待确认请求的编号或修订号。窄窗口详情及放弃确认属于模态操作，完成或关闭后才能切到定时计划或同步诊断；抽屉内进入定时计划会先关闭抽屉。

连接异常导致写入结果不确定时，界面保留原请求并阻止其他写入。使用原请求确认保存或移动，不能靠刷新重新创建。超出请求确认窗口时会明确提示无法再核对；须先检查现有记录，再明确结束该次重试，不能把过期请求当成未执行。

## 在对话中记录普通任务

例如：“把这件事记到产品迭代项目，下一步是检查错误边界”，或“把这项任务改为等待用户，阻塞项是待确认交互”。Codex 先用 `learning_board_context` 获取项目、任务与最新 revision，再用 `learning_board_task` 写入。

该模型工具只允许在已有活动项目中新建任务，或更新活动任务的状态、当前步骤和阻塞项。它不能归档、恢复、删除记录、调整已有任务的优先级或截止日期，也不能操作 Codex 原任务。完成状态应依据用户明确报告，不能从空闲或一轮结束推断。

创建时若调用上下文明示当前对话的真实 UUID，Codex 可以传入 `currentThreadId`，服务端自动生成原对话链接；用户无需粘贴链接。宿主当前未承诺提供此 ID，无法确定时保留空链接，不根据标题、缓存列表或插件进程环境猜测。更新只改请求中的字段并保留原链接。

任务写入继续使用 requestId、revision 校验、锁、自动备份和原子保存。结果未知时原样重试同一请求；版本冲突后重新读取，不能重复创建。

## 今日焦点

在未完成、未归档的手工任务“更多操作”中选择“设为今日焦点”，再次选择可移出。待处理视图先显示今日焦点，再显示待处理与接下来；其他任务视图也会标记焦点卡片。Codex 自动任务仍为只读，不支持设置焦点。建议每天最多选择 5 项，这不是硬上限，可继续选择第 6 项。

- **日期与时区**：按选择时的显示日期及 IANA 时区生效，跨日后自动失效；切换显示时区后，原时区的焦点不冒充新时区的今日焦点。完成、归档任务或归档项目会移出焦点。即使任务被搜索或筛选隐藏，仍可通过焦点管理入口移除。
- **保存与共享**：保存至 schema 4 的可选 `dailyFocus` 字段，包含日期、时区和手工任务 ID，随导出及自动备份保存。其他窗口打开、刷新或在无草稿的任务视图恢复激活时读取同一份记录；编辑或写入保护期间延迟读取。
- **兼容**：没有日期的旧浏览器焦点视为过期。旧 schema 4 文件可以读取，无须为打开页面迁移写盘；恢复不含焦点的旧备份会清空焦点。旧版插件不保证能读取含新字段的文件。

## 学习计划与日历

看板任务记录长期目标与进度，学习时段记录哪天几点做什么；任务截止日期不会自动变成学习安排。一个任务可安排多次学习，完成一次时段不会自动把整个任务标为完成。

从侧栏“学习安排”进入，今日／周日历切换位于日历工具栏。“复制学习排程提示”可以生成对话提示；剪贴板不可用时展开已选中的文本供手动复制。返回全部任务或选择项目时切回任务列表；日历操作继续保留原有草稿和筛选。

- **日历工具栏**：学习安排只显示日历范围、导航、显示时区与时段操作，不显示任务搜索及任务计数。显示时区使用按界面语言展示的候选下拉，保留本机及已保存的有效 IANA 时区。
- **今日**：按选定显示时区查看当天安排，突出正在进行或最近的下一项，已完成和已取消记录默认折叠，未完成记录保持可见。剩余安排分钟只统计今天尚未过去的计划时段，不代表已学习时间，也不会把超时记录自动标为完成。可见且空闲的日历会按分钟更新当前项、剩余时间和日期；编辑、输入或保存期间暂缓，避免打断操作。
- **周日历**：以周一为起点查看一周，支持上周、下周、回到今天及新增学习时段。卡片显示时间、任务、状态和时长，展开“本次详情”查看目标、标准、反馈与操作。按实际内容区宽度切换七列概览或纵向日程；跨日时段按显示时区呈现。
- **安排与反馈**：选择任务、日期、起止时间、时区，并填写学习目标与完成标准；完成后可记录“本次完成”或“未完成”、实际分钟数与反馈。反馈面板显示打开时的本次日期时间、时区、目标和标准。未完成原因可快速加入可编辑的反馈文字，不会覆盖已有内容或自动保存。用户可以提前完成安排。
- **重排保护**：只允许调整尚未开始且仍为计划状态的时段；不能更换其所属任务，也不能用重新排程覆写既有反馈。取消保留记录。整项任务的完成仍使用任务状态操作。
- **冲突检查**：活动任务的计划时段不能互相重叠，相邻的结束/开始时间可以相同。批量调整按最终结果检查，任一错误会拒绝整批。已完成、未完成及取消时段保留历史。
- **时区**：保存 UTC 时间点和 IANA 时区，显示按用户选定的时区转换。夏令时跳过或重复的本地时间不会被静默挪动；请选择其他时间，或切换到 UTC 明确输入。

当前不连接 Apple/Google 日历，不读取个人日历忙闲、不发送日历提醒，也未创建每天自动运行的学习提醒。模型规划只能根据你提供的可用时间和看板内已有安排避开冲突。

### 让 Codex 规划

插件更新后，在启用了此插件的 Codex 对话中可以说：

> 我想用四周学习 Python，目前零基础。工作日北京时间 20:00–21:00、周末 14:00–16:00 可以学习，目标是能写一个整理文件的小工具。请先读取任务看板，创建学习项目，把未来七天拆成有明确练习和完成标准的学习时段；每天留出复习时间，不移动已有安排。

再次调整时，可以说：

> 今天的文件遍历练习没有完成，实际学了 20 分钟，卡在路径处理。请记录这次反馈，保留学习历史，并根据下周可用时间为剩余内容增加安排。

模型使用 `learning_board_context` 读取完整记录、当前 revision 和服务端时间，再用 `learning_board_plan` 原子提交安排。模型不内置在看板页面里；界面不会假装执行 AI 排程。缺少学习目标、基础、时区或可用时间时，应先在对话中补齐。项目说明可以保存目标与时间约束，时段保存具体学习目标、完成标准与用户反馈，供后续规划使用。

规划时只创建必要的项目和新任务，既有任务由 ID 关联。新建时段省略 ID，更新未来时段携带已有 ID。规划不会批量覆盖所有任务、归档记录或恢复备份；学习反馈工具只能记录用户明确提供的事实。遇到未知写入结果，应使用同一 requestId、revision 和原参数重试；明确版本冲突后再读取并重新规划，不能把旧安排再次创建。

## 导出、备份与恢复

“导出记录”生成经过校验的 JSON，包含项目、任务、学习时段与反馈、归档、优先级、日期及填写的链接，不包含内部请求历史。导出由界面主动调用只读 App 工具；不发送到模型上下文。下载由宿主支持情况决定，界面提供可复制的导出内容作为替代。

恢复流程为选择备份、校验并预览项目/任务/学习时段数量、明确确认恢复。恢复会用备份内容替换当前项目、任务和学习时段；提交前自动备份现有数据。它是一次新的保存，保留当前请求历史并增加当前修订号，不采用备份中的旧修订号回退本机版本。预览后记录若变化，提交被版本冲突拦截，须重新预览。

每次有效保存前，已有数据文件会备份到同一数据目录的 `backups/`。通常保留最近 20 份，首次从旧 schema 2 迁移的原始备份另行保留。备份失败会阻止本次提交；提交后清理旧备份失败不会把已成功保存报告成失败。新库第一次保存没有旧文件可备份。

普通备份文件名包含原修订号及原始字节 SHA-256；永久迁移备份由 `schema2-migration.json` 和 `schema2-migration.sha256` 配对组成。维护列表逐项标记校验结果，损坏项不会妨碍导出其他有效备份；缺少校验值的旧备份不能直接导出。

备份具有校验值并拒绝损坏、超限、无效关联和不安全路径。当前主数据文件损坏时，在线恢复仍会拒绝写入；关闭所有看板后，可用维护工具 `restore-backup` 把校验通过的本机备份装回为 `data.json`，损坏文件另存为 `data.damaged-<时间>.json`，不删除。这里没有承诺完整断电事务或磁盘硬件失效后的恢复。

## 临时数据预览

```sh
npm run preview
```

打开终端输出的 `PREVIEW_URL`。默认预览仅绑定本机回环地址，使用新建的系统临时目录及合成示例，支持真实存储层的任务编辑、今日焦点、学习安排、反馈、归档、排序、导出和恢复，不读写正式记录。`npm run preview -- --codex-live` 可在明确标注下只读实际 Codex 元数据；“我的看板”中的手工记录仍为临时示例，自动任务使用只读元数据；预览和面板都不会发送创建或修改计划的消息。

每次预览由独立看护进程创建自己的 `learning-board-ui-preview-*` 目录。预览退出、启动失败、收到 Ctrl+C / SIGTERM / SIGHUP，或预览进程单独被 SIGKILL 时，看护通过连接断开清理本次目录。看护不扫描、删除其他预览或旧目录。若看护也被强制结束或电脑断电，仍可能残留目录；需先确认对应预览已停止，再单独核对处理，不能只按目录前缀批量删除。

预览不进入发布插件包，不替换客户端插件，也不代表真实宿主中的权限、下载或链接跳转已经验收。

## 界面源码结构

`src/view.mjs` 负责挂载、模块连接及读取协调。`view-state.mjs` 集中保存宿主、活动、编辑器、备份、反馈和查看状态；`write-state.mjs` 以纯函数维护保存、移动、归档/恢复三个请求槽。已经明确失败的保存请求可以与待确认的移动请求共存；一次网络活动仍互斥。不确定请求保留原编号、修订号和参数，过期请求须经过刷新、核对和明确结束。

卡片、列、编辑器、备份、反馈、显示与写入流程分别位于 `view-*.mjs`。DOM 仍同步更新，并保留现有 ID、原生菜单结构以及焦点和滚动恢复。CSS 位于 `src/app.css`；`scripts/app-template.mjs` 为生产构建、临时预览和组件测试内联同一份样式。构建指纹覆盖所有界面模块、CSS 与模板加载器，发布时不会请求独立样式文件。

## 本机持久保存和兼容

正式入口的唯一主数据文件为：

```text
~/Library/Application Support/LearningBoard/data.json
```

生产入口不接受 MCP、CLI 或专用环境变量提供的自定义存储目录。Node 主目录解析会参考运行环境的 `HOME`。测试工厂可注入临时目录。

旧 schema 2/3 文件经过各版本的严格校验后在内存中升级为 schema 4，并补上空学习时段；只读或历史请求重放不会迁移写盘。首次有效写入前通过原字节备份保留旧版本，再保存 schema 4。schema 2 的永久迁移备份仍保留。已有 ID、手动状态、数组顺序、记录时间与请求收据均保留。schema 4 磁盘缺少学习时段字段会按损坏数据拒绝。

旧 schema 3 导出备份先按原始内容校验 checksum，再升级恢复；恢复旧备份会把当前学习时段替换为空，预览会明确显示零个时段。

每次提交先取得进程锁（`.save-lock.sqlite` 上的 SQLite 写事务，进程退出时由系统释放，最多等待 2 秒），再建立兼容用的 `.save-lock` 目录标记，然后重新读盘、请求去重、修订号比较、备份、同目录临时写入、文件 fsync 及原子 rename。新目录权限为 `0700`，新文件为 `0600`。未知 schema、损坏文件、无效关联、超限及符号链接会被拒绝，不会自动清空。

上限为 500 个项目、5,000 个任务、20,000 个学习时段及 16 MiB 主文件。单次规划最多创建 50 个任务、安排或调整 100 个时段。请求历史保留最近 1,000 个成功请求，并继续滚动；旧版本留下的最多 10,000 条历史仍可读取，下次保存时裁剪到 1,000 条。保留窗口内，同请求编号及相同规范化参数重放不重复创建；同编号不同参数拒绝。历史之外的旧请求返回 `REQUEST_EXPIRED`，不当成新的写入执行。日志独立保留连续修订范围，不能直接手工删日志或回退 revision。

## 锁诊断与离线恢复

`.save-lock/owner.json` 记录拥有者 token、PID、主机及创建时间。持有进程锁的写入者若发现遗留标记，且其拥有者是本机已不存在的进程（或本进程自己未清理的标记），会把它改名隔离为 `.save-lock-quarantine-<uuid>` 后继续保存；其他主机、仍存活的进程或内容异常的标记不会被接管。时间只用于诊断，不按锁年龄抢锁。

维护入口位于构建后的 `plugins/codex-task-board/dist/maintenance.js`：

```sh
npm run maintenance -- inspect-lock
npm run maintenance -- list-backups
npm run maintenance -- export-backup BACKUP_NAME --output /absolute/path/backup.json
npm run maintenance -- restore-backup BACKUP_NAME --confirm-all-clients-stopped
```

导出目标必须不存在，维护工具不会覆盖已有文件。锁恢复前须先关闭所有看板宿主，检查 `inspect-lock` 给出的身份，再按工具帮助传入相同身份及显式的全部客户端已停止声明。活跃 PID、不可检查的进程、符号链接、未知文件或变更的锁会被拒绝。恢复会把已核对的锁隔离保存，不递归删除诊断材料；期间不得重新启动宿主。

```sh
npm run maintenance -- --help
```

这属于显式离线操作，不是自动崩溃恢复或操作系统级强制限制。本轮开发验证不会在正式数据目录执行这些命令。

## 协议

- `learning_board({})`：只读 global 入口，返回 `{ok:true,board}`。
- `learning_board_codex({})`：App 专用只读入口，返回独立 `{ok:true,snapshot}`，包括线程、自动化和各来源的完整性、采集时间与错误状态。
- `learning_board_codex_sync({capturedAt,limit,result})`：模型专用的受限采集入口，只保存用户授权采集的线程元数据，返回写入回执；不控制线程或调度、不改变手工看板。
- `learning_board_task({requestId,expectedRevision,operation})`：模型专用普通任务写入；`create_task` 的 `task` 使用已有 `projectId`、`title` 和可选 `status/priority/dueDate/currentStep/blocker`，`currentThreadId` 位于 operation 中；`patch_task` 使用 `taskId`，`patch` 仅允许 `status/currentStep/blocker`，至少一个字段。
- `learning_board_mutate({requestId,expectedRevision,operation})`：App 专用写入；支持 `save_project`、`save_task`、`patch_task`、`create_task`、`move_task`、`archive_project`、`archive_task`、`restore_board`、`save_session`、`record_session_feedback`、`cancel_session`、`apply_schedule`。普通编辑携带已有 ID，新建省略 ID；时段 ID 和更新时间由服务生成。批量规划中的新项目、新任务使用客户端 UUID，便于在同一批次关联，不能覆盖已有 ID。
- App 写入成功返回 `{ok:true,board,replayed,appliedRevision,entityId?,changed?}`；创建请求的实体 ID 随请求回执持久保存，重放得到同一 ID。
- 模型写入工具（`learning_board_task/plan/feedback`）只返回回执 `{ok,replayed,appliedRevision,revision,entityId?,changed?}`，`changed` 含本次写入的完整项目、任务与时段记录，不返回整张看板；失败结果也不附带看板，冲突后应重新调用 `learning_board_context`。
- `learning_board_data({action:'export'})` 返回 `{ok:true,backup}`；`{action:'preview_restore',backup}` 返回 `{ok:true,board,preview}`。备份封装含 format、formatVersion、createdAt、公开 board 与 checksum。
- 业务错误返回 `isError:true` 和 `{ok:false,error:{code,message},board?}`。严格工具 schema 失败由 SDK 返回 MCP 错误，不进入事务。

schema 4 项目含 `id/name/description/lastUpdatedAt/archivedAt`；任务含 `id/projectId/title/status/sourceTool/currentStep/blocker/lastUpdatedAt/conversationUrl/archivedAt/priority/dueDate`；学习时段含 `id/taskId/startAt/endAt/timeZone/status/objective/completionCriteria/feedback/actualMinutes/lastUpdatedAt`；看板含 `schemaVersion/revision/projects/tasks/sessions/syncState/persistence`。`syncState` 始终为 `unsynced`。链接只允许无账号密码的 HTTP(S) 或严格的 `codex://threads/<UUID>`，不会读取链接内容。

原写入和备份工具保持 App 可见；只读看板入口注册 global entrypoint，并对模型可见，使“打开任务看板”可以由模型调用。模型可调用的 `learning_board_context({includeArchived?})` 返回 `board`、`serverNow` 与 `omitted` 计数，默认省略已归档的项目、任务及其时段；`learning_board_plan({requestId,expectedRevision,operation})` 只接受 `apply_schedule`，其中含可选 `newProject`、`newTasks` 和 `sessions`；`learning_board_feedback` 只接受 `record_session_feedback`。这两个学习写入工具不能调用恢复备份、归档或任意任务修改。普通任务使用单独的受限工具。资源 CSP 网络及远程资源域名单为空，不加载远程脚本、字体或样式。图标和打包依赖许可证随插件分发。SDK 回调在 connect 前注册。
